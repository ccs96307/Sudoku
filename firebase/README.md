# Still Sudoku Cloud

This is the shared Firebase backend used by the static web, Flutter, and
PySide6 desktop clients. It provides email/password and Google sign-in, a
Taipei-time daily puzzle, a server-validated daily leaderboard, account game
sync, and private profiles.

## Create and configure a Firebase project

1. Create a Firebase project and a Cloud Firestore database in **asia-east1**.
2. In **Authentication → Sign-in method**, enable **Email/Password** and
   **Google**. Add your hosted web domain to the authorized domains.
3. Register the web, Android, and iOS apps. Copy the web app config into
   `web/firebase-config.js`; this config contains public app identifiers, not
   server credentials.
4. Copy `.firebaserc.example` to `.firebaserc` and replace the sample project
   ID. Keep the personal `.firebaserc` local if the repository is public.
5. Install the Firebase CLI, sign in, and deploy from this directory:

   ```bash
   npm install --global firebase-tools
   firebase login
   firebase deploy --only firestore:rules,firestore:indexes,functions
   ```

The Functions use Node.js 22 in `asia-east1`. Daily puzzle generation is
on-demand and idempotent: the first authenticated request creates that day's
puzzle; all later players receive the same board. The answer is stored in a
separate collection that clients cannot read. A submitted result must contain
the exact valid solution. The server keeps each player's best time and adds a
two-minute penalty per hint. Runs using the solution-reveal action are not
ranked.

## Web

Edit `web/firebase-config.js` with the values from the Firebase web app setup.
Use an HTTP server or GitHub Pages; opening `index.html` with `file://` disables
module imports and cloud sign-in. The regular game remains playable as a guest.

## Flutter

From `flutter_app/`, pass the Firebase app options as Dart defines. App IDs are
platform-specific:

```bash
flutter run \
  --dart-define=FIREBASE_API_KEY=your-api-key \
  --dart-define=FIREBASE_PROJECT_ID=your-project-id \
  --dart-define=FIREBASE_MESSAGING_SENDER_ID=your-sender-id \
  --dart-define=FIREBASE_AUTH_DOMAIN=your-project.firebaseapp.com \
  --dart-define=FIREBASE_WEB_APP_ID=your-web-app-id \
  --dart-define=FIREBASE_ANDROID_APP_ID=your-android-app-id \
  --dart-define=FIREBASE_IOS_APP_ID=your-ios-app-id
```

Use the same defines with `flutter build web` for the hosted Flutter edition.
For Android and iOS, register each app in Firebase and follow the platform
setup generated by `flutterfire configure` if you later add platform-specific
Firebase plugins.

## PySide6 desktop

The desktop client uses Firebase's HTTPS APIs directly. Configure the public
Firebase API key and project ID in the environment. Google sign-in also needs
a Google OAuth client whose type is **Desktop app**; its loopback redirect uses
PKCE and the token is held only in memory.

```bash
export STILL_SUDOKU_FIREBASE_API_KEY=your-api-key
export STILL_SUDOKU_FIREBASE_PROJECT_ID=your-project-id
export STILL_SUDOKU_GOOGLE_CLIENT_ID=your-desktop-client-id
uv run python main.py
```

For email/password registration, Google client ID is not needed. Desktop
credentials are not persisted; sign in again after restarting the app.

## Local emulator

From this directory, run `firebase emulators:start --only auth,functions,firestore`
for local testing. The clients currently use the production endpoints and need
explicit emulator wiring before they can connect to these local emulators.

## Cost estimate

Firebase Authentication for email/password and Google sign-in is included at
no cost. Firestore's free quota currently includes 1 GiB stored, 50,000 reads
and 20,000 writes per day, plus 10 GiB monthly outbound transfer. Cloud
Functions require the Blaze billing plan, even though it includes monthly
no-cost quotas (currently 2 million invocations, 400,000 GB-seconds, and
200,000 CPU-seconds). There is no fixed monthly subscription, but usage above
the free quotas is billed at the published rates. A small personal Sudoku
community will likely fit within the included quotas, but traffic and data
retention determine actual costs. Set a billing budget alert before inviting
many users; budget alerts notify you and do not stop charges automatically.

Current plan and usage details: [Firebase pricing](https://firebase.google.com/pricing/),
[Firestore pricing](https://firebase.google.com/docs/firestore/pricing), and
[Cloud Functions quotas](https://firebase.google.com/docs/functions/quotas).
